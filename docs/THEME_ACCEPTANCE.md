# Article theme acceptance

Date: 2026-09-09. Scope: four bundled article themes in this checkout.

This report separates local verification from live Share Note behavior. The local visual fixture contains only synthetic public-safe content and never requires a real API credential or note key.

## Reproduce

```bash
npm ci
npm run build
npm test
node scripts/verify-themes.mjs /absolute/path/to/local-artifacts
```

The visual script requires an already available Playwright installation. If it is outside this checkout, set `PLAYWRIGHT_MODULE` to its absolute module path. Optionally set `CHROME_EXECUTABLE` to an existing Chromium/Chrome binary. These are developer verification tools, not plugin runtime dependencies.

The script uses the freshly built CLI, a temporary project and user-data directory, synthetic credentials and `.invalid` service origins. It generates each theme from `examples/theme-fixture.md`, opens the preview in an isolated headless browser, blocks network requests and checks page overflow at 1440 and 375 CSS pixels. It writes four standalone HTML previews, eight screenshots and `metrics.json`, then removes temporary credential/project state.

## Local results

- Baseline rerun: 13 files / 87 tests passed.
- `npm run build`: typecheck, 14 files / 105 tests and bundle generation passed.
- `npm test` rerun after the final bundle build: 14 files / 105 tests passed, including clean-bundle acceptance.
- The new bundle's `themes` command returns four styles and system default `simple` without a project or credentials.
- Visual acceptance: all 8 screenshots (four themes at 1440/375 CSS pixels) passed overflow and network checks and were inspected manually. Desktop article widths are 860/1080/740/900 pixels for simple/technical/reading/dark respectively. Every narrow page stays at 375 pixels; code and wide tables scroll locally.
- A generic host stylesheet injected after theme CSS did not change checked colors, fonts, line heights or backgrounds. This caught and led to a fix for inherited code line height. This is not a replica of the live service stylesheet.
- No remote resource requests were observed. Four themes generated four different hashes from the same fixture.
- Review also found that saved preview bodies needed a fresh SHA-256 check before any write. The fix and local body/CSS tamper regressions pass before any remote/key/operation write. Theme metadata is also checked against its canonical CSS wrapper. A post-submit CSS tamper test returns `submitted_unverified` while preserving the previous record hash/theme; a controlled project-lock race rejects theme-only rebind.
- `git diff --check` passed.

Local artifacts are generated by the reproduction command above: `index.html`, each theme's HTML, eight PNG screenshots and `metrics.json`. They contain only the public-safe fixture.

## Main integration verification

After integrating the latest main browser-binding and branding changes, typecheck and all 116 tests across 14 files passed against the rebuilt bundle. Both the Codex browser commands and the no-request `themes` command are retained.

## Evidence scope

- Automated contracts cover theme selection, project-state preservation, record-bound update previews, legacy unthemed records, encrypted round-trips and tamper detection.
- Local visuals check typography, colors, spacing, long code and wide tables in the generated preview shell. They do not reproduce all service styles or scripts.
- Source sanitization remains separate from the trusted theme wrapper. HTML and Markdown reading outputs intentionally omit styling.

## Live acceptance outstanding

No dedicated test article or real publication credentials were provided to this task. No existing share was changed, and no real note keys or credentials were copied into this worktree. Public/self-hosted publication, online CSS cascade, post-decryption service initialization, online update and CDN behavior remain unverified.

To complete live acceptance, authorize a dedicated test article on an explicitly selected service and supply access through the normal local setup flow. Preview and publish the fixture, inspect all four themes at desktop/narrow widths through authorized theme updates, verify decrypted content hashes after every write, then delete the test article only if cleanup is authorized. Do not reuse an existing production share for this test.
